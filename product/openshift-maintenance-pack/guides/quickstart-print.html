Three result words

  • OBSERVED: a narrow expected field value is present.
  • REVIEW: investigate a condition or difference.
  • UNKNOWN: the evidence is insufficient.
No result means “upgrade-ready”, “approved” or “compliant”. Exit code 0 means artifacts were generated, even when review items remain.

Python 3.9+ only. No oc, hosted service, AI model, extra Python package or cluster is required for the offline example.

02 / Prepare a real pilot separately

Collect less.
Keep the context.

  1. Authorise: review the script, select a trusted context and confirm narrow read permissions on a designated non-production OpenShift cluster.
  2. Capture: use explicit before/after phases and new private output directories. Four fixed oc get queries are allowed.
  3. Compare: retain manifests, inspect changed membership and investigate REVIEW/UNKNOWN items.
  4. Complete the record: add the supported update-path assessment, Development validation, recovery evidence and independent decision through your existing process.

Designed to minimise local output

Selected versions, condition statuses and pool counts are retained. Cluster/node identities are hashed. Raw responses, messages, annotations, addresses, context names and credentials are not persisted.

Output is still operationally sensitive. Hashes are not guaranteed anonymisation, trusted signatures or evidence of authentic collection. Protect the files and follow your retention policy.

Before operational use

Complete live compatibility and permission testing, independent engineering review, usability validation and your organisation’s operational approval. The package contains a checklist for those release gates.

Read README.md, guides/security-and-scope.md and VALIDATION.md for the exact scope. No upgrade or real cluster command was executed to create this preview.
